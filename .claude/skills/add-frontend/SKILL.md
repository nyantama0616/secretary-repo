# フロントエンド実装: $ARGUMENTS

対応するバックエンド（tRPC ルーター）が実装済みであることを前提とする。

以下の手順でフロントエンドを実装する。

**重要: 各ステップの完了時にユーザーの承認を得てからコミットする。承認なしにコミットや次のステップへの移行を行ってはならない。**

## 1. ガイドラインを把握する

実装に入る前に、以下のドキュメントを読んで方針を把握する。

- [UX 設計ガイドライン](https://docs.bi-shop-it.com/llms.mdx/docs/guidelines/ux-design) — ユーザビリティヒューリスティクス・設計原則・アニメーション設計
- [フロントエンド実装ガイドライン](https://docs.bi-shop-it.com/llms.mdx/docs/guidelines/frontend) — コンポーネント設計・tRPC 呼び出し・エラー表示などの規約
- [`@bi-shop-it/ui` ドキュメント](https://docs.bi-shop-it.com/llms.mdx/ui) — 使用するコンポーネントの API とトークンを確認する。実装中に DS コンポーネントを使う際は、必ずこのドキュメントで使い方を確認してから使う

## 2. ⏸️ UX/UI を設計する

以下の順で設計し、ユーザーに提示する。装飾は最低限にとどめ、UX を重視する。見た目は後からリッチにできる余地を残す。

1. **ユーザーフローを定義する**: 対象機能の受け入れ条件から、ユーザーが目的を達成するまでの操作手順を洗い出す。画面遷移・分岐・エラー時の動線を明確にする
2. **ワイヤーフレームを作成する**: ユーザーフローに基づき、`dev/<feature>/page.tsx` にモックページを作成する。レイアウトと情報配置に集中し、各画面の状態（ローディング・空・エラー）も考慮する
3. **ユーザビリティを検証する**: ニールセンの10ヒューリスティクスに照らし、明らかな問題がないか確認する

`@bi-shop-it/ui` のコンポーネントを使用する。該当コンポーネントがない場合は、UI ライブラリ側への追加をユーザーに提案する。

→ ユーザーフローとワイヤーフレームを提示し、承認を得てからコミットする。ワイヤーフレームの修正が必要な場合はこのステップ内で対応する。

## 3. フロントエンドを実装する

以下の順で実装する:

1. **page.tsx**（Server Component）: `metadata` の設定と `_components/` 内のメインコンポーネントの呼び出しのみ
2. **_components/ のメインコンポーネント**（Client Component）: データ取得・UI・インタラクションを担当する
3. **UI コンポーネント**: `@bi-shop-it/ui` を使う。該当コンポーネントがない場合は、UI ライブラリ側への追加をユーザーに提案する

- 必要に応じて開発用シード（`src/server/infrastructure/db/seed.ts`）を追加し、画面確認に使う

→ 承認を得てからコミットする。

## 3.5. コードレビュー

`/review-coding` を実行し、実装したコードをレビューする。フィードバックがあれば修正し、承認を得てからコミットする。

## 4. E2E テストを書く

- [テストガイドライン](https://docs.bi-shop-it.com/llms.mdx/docs/guidelines/testing) を読み、E2E テストの責務・検証範囲・テスト名の書き方を確認する
- `e2e/` に機能単位で E2E テストを作成する
- 必要に応じて E2E 用シード（`e2e/seed.ts`）を追加する
- テストを実行し、すべて通ることを確認する

```bash
pnpm --filter web test:e2e
```

→ 承認を得てからコミットする。
