# ユーザーストーリー実装計画: $ARGUMENTS

指定されたユーザーストーリーを分析し、実装可能なタスクに分解する。

**重要: ⏸️ マークのステップではユーザーの承認を得るまで次のステップへの移行を行ってはならない。**

## 1. ユーザーストーリーを読み込む

以下のドキュメントから対象のユーザーストーリーに関する情報を収集する。

- `docs/01-product.md` からプロダクトの目的を確認する
- `docs/02-user-stories.md` から対象 US の詳細と受け入れ条件を読む
- `docs/03-mvp.md` から MVP の方針と対象 US のスコープを確認する

対象 US の受け入れ条件がプロダクトの目的（先延ばしの解消とモチベーション維持）と明らかにずれている場合は、実装に進む前にユーザーに指摘する。

## 2. 既存実装との差分を調査する

以下の各層を調査し、対象 US を満たすために不足している部分を特定する。

- **DB スキーマ**: `src/server/infrastructure/db/schema/` にテーブル・カラムの不足がないか
- **Domain 層**: `src/server/domain/` にエンティティ・リポジトリ IF・ドメインエラーの不足がないか
- **UseCase 層**: `src/server/usecase/` にユースケースの不足がないか
- **API 層**: `src/server/api/routers/` に tRPC プロシージャの不足がないか
- **フロントエンド**: `src/app/` の既存ページ・コンポーネントを確認する。現状のフロントエンドは仮実装であり、活用しても全く別のものに置き換えてもよい
- **MCP 層**: `src/mcp/` に AI エージェント向けのツールの不足がないか
- **ルート定義**: `src/constants/routes.ts` にルートの不足がないか

## 3. ⏸️ 実装計画を提示する

以下の形式で計画をユーザーに提示し、承認を得る。

### 提示する内容

1. **受け入れ条件と実装タスクの対応表**: 受け入れ条件ごとに、必要な実装タスクをリストアップする
2. **実装タスク一覧**: 以下の情報を含む
   - タスクの内容
   - 種別（`add-backend` / `add-frontend` / `add-feature` のいずれで実装するか）
   - DB マイグレーションの有無
3. **実装順序**: 依存関係に基づいた順序。原則として DB スキーマ → バックエンド → フロントエンドの順とする

### 注意事項

- 実装計画のスコープはこのリポジトリの責務（Web UI + MCP サーバー）に限定する。AI エージェント側の変更が必要な場合は `docs/agent-notes.md` に追記し、実装タスクには含めない
- 一つの受け入れ条件が複数のタスクに分かれる場合がある
- 複数の受け入れ条件が一つのタスクでまとめて満たされる場合もある
- 既存実装で既に満たされている受け入れ条件は「実装済み」と明記する
- ダッシュボードを起点に機能を追加していく方針のため、対象 US の情報をダッシュボードにどう反映するかをフロントエンドのタスクに含める

## 4. 計画をファイルに保存する

承認された計画を `docs/plans/US-XXX.md` に保存する。このファイルだけで新しいコンテキストが作業を引き継げる情報量にすること。

```markdown
# US-XXX: ストーリー名

## 受け入れ条件と実装タスクの対応

| 受け入れ条件 | タスク |
|---|---|
| 条件1の内容 | タスク1, タスク2 |
| 条件2の内容 | タスク2 |
| 条件3の内容 | 実装済み |

## タスク

### タスク1: タスクのタイトル

- **種別**: `/add-backend`
- **DB マイグレーション**: あり / なし
- **詳細**: このタスクで何を実装するか。関連するエンティティ、属性、リレーション、プロシージャ名など、Skill の実行に必要な情報を記載する

### タスク2: タスクのタイトル

- **種別**: `/add-frontend`
- **DB マイグレーション**: なし
- **詳細**: ...

## 進捗

- [ ] タスク1
- [ ] タスク2
```

## 5. 次のタスクを実行する

計画ファイルから未完了の次のタスクを一つ選び、対応する Skill（`/add-backend`、`/add-frontend`、`/add-feature`）で実行する。タスク完了後、計画ファイルのチェックボックスを更新する。

コンテキストが切れた場合は、新しいコンテキストで `/plan-story US-XXX` を再実行する。計画ファイルが既に存在する場合はステップ 1〜4 をスキップし、このステップから再開する。
