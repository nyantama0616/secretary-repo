# US-005: AIによる日報作成支援

## 前提

- 日報のCRUD（DB スキーマ、Domain、UseCase、API、MCP、フロントエンド）は US-001 で実装済みである
- 振り返りのセクション構成（良かった点・良くなかった点・学び気づき・次にやること・その他）はDBスキーマで固定せず、AIエージェント側でテンプレートとして管理する。AIが `review` フィールドにマークダウンとして書き込み、フロントエンドの `MarkdownViewer` で表示する
- AIの日報作成ロジック（タスク結果の要約、質問による情報補完、提案の修正）はAIエージェント側の責務である

## 受け入れ条件と実装タスクの対応

| 受け入れ条件 | タスク |
|---|---|
| AC1: US-004完了後、AIが日報の作成を促せる | 実装済み（MCP `create_daily_report`） |
| AC2: その日のタスク結果をもとに、AIが日報の内容を提案できる | 実装済み（MCP `list_tasks` + `update_daily_report`） |
| AC3: 日報がセクション構成を持つ | 実装済み（テンプレートはAIエージェント側で管理） |
| AC4: 情報が不足している場合、AIが利用者に質問できる | スコープ外（AIエージェント側の責務） |
| AC5: 利用者が提案を承認・フィードバック・手動編集で確定できる | 実装済み（編集フォーム） |
| AC6: 確定した日報がDBに保存される | 実装済み |
| ダッシュボードで日報の内容を確認できる | タスク1 |
| ダッシュボードから日報を書くためのボタンがある | タスク1 |

## タスク

### タスク1: ダッシュボードに日報の内容表示と日報作成ボタンを追加する

- **種別**: `/add-frontend`
- **DB マイグレーション**: なし
- **詳細**:
  - 今日の日報セクションに日報の内容（goal, review など）を表示する。`review` は `MarkdownViewer` でレンダリングする
  - 日報が未作成の場合は「日報を書く」ボタン（作成ページへ遷移）を表示する
  - 日報が作成済みの場合は「編集」ボタン（編集ページへ遷移）を表示する
  - E2E テストを更新する
  - 既存コンポーネント: `Dashboard`（`app/_components/dashboard.tsx`）、`DailyTaskSection`（`app/_components/daily-task-section.tsx`）
  - 日報データは `Dashboard` で既に `dailyReport.list` から取得済みである。`todayReport` にフルオブジェクト（goal, summary, review, notes 等）が入っている

## AI エージェント側への申し送り

`docs/agent-notes.md` に以下を記載する:

- 振り返りテンプレートの管理はAIエージェント側の責務である
- テンプレートは What? / So What? / Now What? フレームワーク（Borton 1970）に基づく
- AIは `update_daily_report` の `review` フィールドにマークダウン形式で振り返りを書き込む
