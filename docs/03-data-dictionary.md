# データディクショナリ

本ドキュメントでは、ユーザーストーリーを満たすために必要なリソースとその属性を定義する。
DB設計の前段階として、「何のデータが必要か」「なぜ必要か」を明確にすることが目的である。

## 凡例

| 項目 | 説明 |
|---|---|
| 属性名 | データの名前 |
| 説明 | その属性が表す内容 |
| 必須/任意 | そのリソースにおいて必須か任意か |
| 根拠 | その属性が必要である理由。ユーザーストーリー番号で参照する |

---

## リソース一覧

| リソース名 | 説明 |
|---|---|
| タスク | その日にやるべきことを明確にし、達成度と未達成の原因を記録するもの |
| プロジェクト | 利用者が達成したい目的を定義し、タスクの拠り所となるもの |
| 日報 | その日の振り返りの機会を与え、学び・気づき・評価を蓄積するもの |
| 週報 | 一週間の進捗・停滞を振り返り、短期的な行動傾向を把握するもの |
| 月報 | 一ヶ月の活動を振り返り、目的に対する前進度や中長期的な傾向を把握するもの |

---

## タスク

その日にやるべきことを明確にし、タスク漏れを防ぎ、達成度を記録するもの。達成できなかった場合はその原因も記録し、AIがアドバイス・タスク作成・優先順位づけを行う際の参考情報として活用される。また、AIが日報の内容を提案する際の材料にもなる。日報に紐づき、日単位でスケジューリングされる。

未達成のタスクを繰り越す場合は、新しいタスクを複製して翌日の日報に紐づける。元のタスクはその日の記録としてそのまま残る。複製されたタスクは繰り越し元への参照を持ち、AIが繰り越しの連鎖を追跡して先延ばしパターンを検出するための材料になる。

| 属性名 | 説明 | 必須/任意 | 根拠 |
|---|---|---|---|
| タイトル | タスクの内容を端的に表す名前 | 必須 | - |
| 詳細 | タスクの具体的な内容や補足情報 | 任意 | タイトルだけでは伝わらない情報を補足するため |
| ステータス | 未着手 / 着手中 / 完了 / 中止 | 必須 | US-003: ステータスの遷移が定義されている |
| 並び順 | その日のタスクの中での取り組む順番 | 必須 | US-001: 提案に取り組む順番が含まれる |
| 期限 | タスクを完了すべき日時（時刻を含む） | 任意 | 期限が決まっているタスクの場合、AIが優先順位づけの判断材料に使う |
| 所要時間見積 | タスクにかかる想定時間 | 任意 | US-002: 割り込み時にAIが残り時間を考慮して再構成するための材料 |
| 未達成理由 | 「今度やる」「中止」とした場合、その理由 | 条件付き必須 | US-004: 振り返り時にAIが理由を問い、利用者が回答する。AIの分析・提案の参考情報になる |

**リレーション:**

| 対象リソース | 関係 | 説明 |
|---|---|---|
| 日報 | 多対1 | タスクは1つの日報に属する。日報を通じて「いつのタスクか」が決まる |
| プロジェクト | 多対1 | タスクは1つのプロジェクトに属する。プロジェクトに属さないタスクもあり得る（US-008） |
| タスク（繰り越し元） | 多対1 | 繰り越しで複製された場合、元のタスクへの参照を持つ。AIが先延ばしパターンを検出する材料になる |

---

## プロジェクト

利用者が達成したい目的を定義し、タスクの拠り所となるもの。タスクが「何をするか」を表すのに対し、プロジェクトは「なぜそれをするのか」を表す。利用者が目的を見失わず、行動と目的の紐づきを常に意識できるようにする。

| 属性名 | 説明 | 必須/任意 | 根拠 |
|---|---|---|---|
| プロジェクト名 | プロジェクトを識別する名前 | 必須 | US-008: AIが質問する項目として挙げられている |
| 目的 | このプロジェクトで達成したいこと | 必須 | US-008: AIが質問する項目として挙げられている。タスクの拠り所となる中核的な属性 |
| ステータス | 進行中 / 完了 | 必須 | US-010: ダッシュボードでプロジェクト一覧を表示する際に、進行中と完了を区別するため |
| 期限 | プロジェクトの完了目標日 | 任意 | US-008: AIが質問する項目として挙げられている |

**リレーション:**

| 対象リソース | 関係 | 説明 |
|---|---|---|
| タスク | 1対多 | プロジェクトは複数のタスクを持つ（US-008: フラットな構造） |

---

## 日報

利用者にその日の振り返りの機会を与えるもの。蓄積された内容は、AIがアドバイス・タスク作成・優先順位づけを行う際の参考情報として活用される。AIはタスクの記録を材料にして日報の内容を提案する。

セクション構成は What? So What? Now What?（Borton 1970 / Driscoll 1994 / Rolfe et al. 2001）に基づく。What?（何が起きたか）はタスクの記録で代替されるため、利用者が記入するのは So What? と Now What? が中心となる。

| 属性名 | 振り返り段階 | 説明 | 必須/任意 | 根拠 |
|---|---|---|---|---|
| 対象日 | - | 日報の対象となる日付 | 必須 | US-005: 一日の終わりに作成される |
| 起床時刻 | - | その日の起床時刻 | 任意 | AIが生活リズムと行動傾向の関係を分析する材料になる |
| 就寝時刻 | - | その日の就寝時刻 | 任意 | AIが生活リズムと行動傾向の関係を分析する材料になる |
| 良かった点 | So What? | その日うまくいったこと・評価できる行動 | 任意 | 日報の目的: 振り返りと蓄積。AIが行動傾向を分析する材料になる |
| 良くなかった点 | So What? | その日うまくいかなかったこと・改善すべき行動 | 任意 | 日報の目的: 振り返りと蓄積。AIが改善提案を行う材料になる |
| 学び・気づき | So What? | その日に得た知識・発見・気づき | 任意 | 日報の目的: 学びと気づきの振り返りと蓄積 |
| 次にやること | Now What? | 今日の振り返りを踏まえて明日以降に取り組みたいこと | 任意 | 振り返りを次の行動に反映するため |
| その他 | - | 上記に収まらない自由記述 | 任意 | - |

**リレーション:**

| 対象リソース | 関係 | 説明 |
|---|---|---|
| タスク | 1対多 | 日報は複数のタスクを持つ。タスクの結果を材料にAIが日報を提案する（US-005） |
| 週報 | 多対1 | 日報は1つの週報に属する。週報を通じて週単位の振り返りに集約される |

---

## 週報

一週間を通して何が進み、何が滞ったかを振り返り、短期的な行動傾向を把握するもの。日報が日単位の振り返りであるのに対し、週報は一週間を俯瞰して繰り返し現れるパターン（例: 週後半に集中力が落ちる、特定の種類のタスクを先延ばしにしがち）を認識する機会を与える。AIはその週のタスク結果と日報を材料にして週報の内容を提案する。蓄積された内容は、AIがアドバイス・タスク作成・優先順位づけを行う際の参考情報として活用される。

週報は2段階のライフサイクルを持つ。週の最初に目標を記入して作成し、週の終わりに振り返りを追記して完結する。

| 属性名 | 振り返り段階 | 記入タイミング | 説明 | 必須/任意 | 根拠 |
|---|---|---|---|---|---|
| 今週の目標 | - | 週の最初 | その週に達成したいこと・意識したいこと | 必須 | 週の行動に方向性を持たせ、目的を見失わないようにするため |
| 今週の成果 | What? | 週の終わり | 一週間で達成できたことの要約 | 任意 | 週報の目的: 何が進んだかの把握 |
| 停滞したこと | What? | 週の終わり | 進まなかったこと・繰り越しが多かったこと | 任意 | 週報の目的: 何が滞ったかの把握 |
| 行動パターンの気づき | So What? | 週の終わり | 繰り返し現れた傾向や癖 | 任意 | 週報の目的: 短期的な行動傾向の認識 |
| 来週以降に改善したいこと | Now What? | 週の終わり | 行動パターンの気づきを踏まえて改善したいこと | 任意 | 気づいたパターンを次の行動に反映するため |
| その他 | - | いつでも | 上記に収まらない自由記述 | 任意 | - |

**リレーション:**

| 対象リソース | 関係 | 説明 |
|---|---|---|
| 日報 | 1対多 | 週報は複数の日報を持つ。日報を通じて対象期間が決まる。日報とそのタスク結果を材料にAIが週報を提案する（US-006） |
| 月報 | 多対1 | 週報は1つの月報に属する。月報を通じて月単位の振り返りに集約される |

---

## 月報

一ヶ月の活動を振り返り、プロジェクトの目的に対してどれだけ前進できたかを把握するもの。週報が短期的な行動傾向を扱うのに対し、月報はより中長期的な視点で、目的と行動のずれや成長の変化を認識する機会を与える。AIはその月のタスク結果・日報・週報を材料にして月報の内容を提案する。蓄積された内容は、AIがアドバイス・タスク作成・優先順位づけを行う際の参考情報として活用される。

セクション構成は日報・週報と同様に What? So What? Now What? に基づく。What?（何が起きたか）は週報・日報・タスクの記録で代替される。

| 属性名 | 振り返り段階 | 説明 | 必須/任意 | 根拠 |
|---|---|---|---|---|
| プロジェクトの進捗 | So What? | 各プロジェクトの目的に対してどれだけ前進したか | 任意 | 月報の目的: 目的に対する前進度の把握 |
| 成長・変化 | So What? | 一ヶ月を通じて感じた自分の成長や変化 | 任意 | 月報の目的: 成長の変化の認識 |
| 目的と行動のずれ | So What? | 本来の目的から外れていた行動や時間の使い方 | 任意 | 月報の目的: 目的と行動のずれの認識 |
| 来月以降に改善したいこと | Now What? | 中長期的な傾向を踏まえて改善したいこと・注力したいこと | 任意 | 中長期的な傾向を次の行動に反映するため |
| その他 | - | 上記に収まらない自由記述 | 任意 | - |

**リレーション:**

| 対象リソース | 関係 | 説明 |
|---|---|---|
| 週報 | 1対多 | 月報は複数の週報を持つ。週報を通じて対象期間が決まる。週報とその日報・タスク結果を材料にAIが月報を提案する（US-007） |
