# US-001: AIによる翌日のタスク提案

## 前提

- Googleカレンダー連携（AC3）は MVP スコープ外とする（`docs/03-mvp.md` に「別途判断」とある）
- AIの提案ロジック・会話制御は別リポジトリ（AIエージェント側）の責務である。このリポジトリでは MCPツール（AIがデータにアクセスする手段）と Web UI（利用者が確認・操作する手段）を提供する

## 受け入れ条件と実装タスクの対応

| 受け入れ条件 | タスク |
|---|---|
| AC1: AIが翌日のタスク案を提示できる | タスク2 |
| AC2: 未完了タスクから優先順位をつけて提案に含められる | タスク1, タスク2 |
| AC3: Googleカレンダーの予定を参照し、不足するタスクを提案できる | MVPスコープ外 |
| AC4: 承認すると翌日のタスクとして確定される | タスク1, タスク2 |
| AC5: フィードバックで再提示できる | タスク2 ※AI側が主体 |
| AC6: 取り組む順番が含まれ、最初に着手すべきタスクが明確 | タスク1, タスク2, タスク3 |
| AC7: 手動でタスクの追加・削除・並べ替えができる | タスク1, タスク3 |

## タスク

### タスク1: タスクAPIを拡張する（フィルタリング・並べ替え・作成時の日報紐づけ）

- **種別**: `/add-backend`
- **DBマイグレーション**: なし
- **詳細**:
  - `GetTasksUseCase` にフィルターを追加する（`dailyReportId`, `status[]`）。現在は `taskRepository.findAll()` で全件取得している
  - `TaskRepository` に `findByFilters(filters: { dailyReportId?, statuses? })` を追加する
  - `ReorderTasksUseCase` を新規作成する。タスクIDの配列を受け取り、配列の順序に従って `sortOrder` を一括更新する
  - `TaskRepository` に `updateSortOrders(items: {id, sortOrder}[])` を追加する
  - `CreateTaskUseCase` の入力スキーマに `dailyReportId` を追加する。指定された場合は日報の存在チェックを行う
  - tRPC: `task.list` にフィルターパラメータを追加、`task.reorder` プロシージャを追加

### タスク2: MCPにタスクツールを追加する

- **種別**: `/add-backend`
- **DBマイグレーション**: なし
- **詳細**:
  - `src/mcp/tools/task.ts` に以下のツールを追加する（既存の `daily-report.ts` と同じパターン）
  - `list_tasks` — フィルター付きタスク一覧（dailyReportId, status で絞り込み）
  - `get_task` — タスク詳細取得
  - `create_task` — タスク作成（タイトル、説明、dailyReportId、projectId、期限、見積もり時間）
  - `update_task` — タスク更新
  - `update_task_status` — ステータス変更
  - `delete_task` — タスク削除
  - `assign_task_to_daily_report` — タスクを日報に紐づけ
  - `reorder_tasks` — タスクの並べ替え
  - 既存の UseCase を呼び出すラッパーとして実装する。MCPツール独自のテストは不要（UseCase は統合テストで検証済み）

### タスク3: ダッシュボードに今日・明日のタスク一覧と操作UIを実装する

- **種別**: `/add-frontend`
- **DBマイグレーション**: なし
- **詳細**:
  - 今日の日報を日付で自動取得し、紐づくタスクを `sortOrder` 順・ステータス付きで表示する
  - 明日の日報が存在する場合、紐づくタスクを表示する
  - 明日のタスクに対して手動操作UIを提供する:
    - タスクの追加（新規作成して日報に紐づけ）
    - タスクの削除
    - タスクの並べ替え
  - 各タスクから詳細画面（`/tasks/[id]`）へ遷移できるようにする
  - 日報が存在しない場合は「タスクなし」の表示とする

#### UX/UI 設計

**ユーザーフロー:**
1. アプリを開く → ダッシュボードが表示される
2. `dailyReport.list()` で今日・明日の日報を日付で検索し、`task.list({ dailyReportId })` でタスクを取得する
3. 今日のタスク: ステータスバッジ付きで閲覧のみ。タスク名クリックで詳細画面へ遷移
4. 明日のタスク: 閲覧 + 手動操作（追加・削除・並べ替え）
5. 日報が存在しない場合: 「タスクはまだありません」と表示

**ワイヤーフレーム:**
```
┌──────────────────────────────────────────┐
│ ダッシュボード                              │
│                                          │
│ 今日のタスク  2026/02/22（日）              │
│ ┌──────────────────────────────────────┐ │
│ │  tRPCルーターを実装する      [未着手]  │ │
│ │  テストを書く                [完了]    │ │
│ └──────────────────────────────────────┘ │
│                                          │
│ 明日のタスク  2026/02/23（月）              │
│ ┌──────────────────────────────────────┐ │
│ │ [タスクを入力...          ] [追加]     │ │
│ │                                      │ │
│ │  ↑↓  APIを設計する            [削除]  │ │
│ │  ↑↓  テスト追加               [削除]  │ │
│ └──────────────────────────────────────┘ │
└──────────────────────────────────────────┘
```

**コンポーネント構成:**
- `app/_components/dashboard.tsx` — メインコンポーネント（データ取得・状態管理）
- `app/_components/daily-task-section.tsx` — 今日/明日のタスクセクション（表示）
- `app/_components/task-add-form.tsx` — タスク追加フォーム（明日のみ）

**既存資産の再利用:**
- `STATUS_CONFIG` / `Badge` — ステータス表示（`tasks/_components/task-list.tsx` のパターン）
- `formatDate` — 日付フォーマット（`lib/format.ts`）
- `Loading` / `ErrorDisplay` — フィードバック（`components/feedback/`）
- `ROUTES.taskDetail(id)` — タスク詳細への遷移
